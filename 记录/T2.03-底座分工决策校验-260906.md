## 二、四处发现与处置

### 发现 ①：T2.03 没有出口物，而 TR-5 是纯人工签字项 —— 缺与不缺在门禁输出里长得一样

`gate_baseline.json` 里 TR-5 是 `"type": "manual"`。T2.03 之前 `记录/` 下没有任何分工决策文件，门禁照样报 PASS——因为「人工项未签字」和「人工项根本不存在」在输出里无法区分。

**处置**：新建决策记录文档，并把它从纯人工降级为**半自动**：新增 `tests/contract/test_base_contract.py` 6 条断言，守八环归属、集成方式、准出映射完整性、缺口不得静默消失。

### 发现 ②：分工表可以纯纸面成立 —— 八环填满却一环没调用

填表时最容易发生的失效是：八环填满、集成方式写 REST、与 §5.4 完全吻合，但**没有任何一环被真正调用过**。实测：

| 环 | 仓库内集成代码 | 本轮自有实例 | 实测状态 |
|---|---|---|---|
| 连接器 | 无 | 无 | 未调用 |
| 深度解析 | `packages/document/parser.py` 是骨架（源码注释写明「real parsing wired to external engine on E1」） | 无 | 未调用 |
| 三索引检索 | `packages/retrieval/service.py` 是骨架（无索引，`retrieve` 直接 `refused=True`） | 无 | 未调用 |

**处置**：分工表新增「E0 实证状态」列，逐环写实为「未调用（能力存在）」，并加断言**禁止把 RAGFlow 三环的实证状态改成「已验证/已跑通/已实测」**——这是本轮最值钱的一条守卫，它防止的不是笔误，是伪造验收。

### 发现 ③：判据源引用歧义 —— 同一本手册里 §5.2 与 §5.3 分属两份文档

手册 02 §T2.03 原写「输入 §5.2、§5.4」「分工建议基线（§5.2）」。本册其他章节的 `§X.Y`（§3.7 / §3.8 / §5.3）默认指 `60.90.03`，但 **`60.90.03` 的 §5.2 是「DSH/WorkBuddy 接入前提」，与底座分工毫无关系**。真实口径在推进方案 v2.2 §5.2（「允许的最小适配」表第一行）。

顺着这条还查到推进方案 v2.2 自己第 270 行也写「（口径见 §5.2）」——它指自己，是对的；但手册 02 照抄进自己的语境就错了。

**处置**：手册 02 §T2.03 全部改为显式文档名，并加注记「凡指向推进方案的一律写文档名」。

### 发现 ④：T1.07 判据只达成三分之二，「可建数据集」从未实证

T1.07 判据（手册 01 §T1.07）为「容器 healthy + 可建数据集 + API 可调」。

| 判据项 | 结果 | 证据 |
|---|:---:|---|
| 容器 healthy | ✅ | `记录/env-E0.md`：Up 5 weeks (healthy)，容器内 :80 返回 200 |
| API 可调 | ✅ | 见下方对照实验 |
| **可建数据集** | ❌ | 需 API Key；既有实例为在用试验环境（项目 `filebay-knowledge-trial`），写入即污染 |

**API 可调性实测（含对照实验）**：

```
GET /                          → 200   # Web 首页
GET /api/v1/datasets           → 401   # {"code":401,"message":"<Unauthorized '401: Unauthorized'>"}
GET /api/v1/zzz-not-exist-260906 → 404   # 对照①：不存在的 API 路径
GET /zzz-random-260906           → 200   # 对照②：随机顶层走前端 SPA 兜底
```

> **为什么必须做对照**：如果任意路径都返回 401，那 `/api/v1/datasets` 的 401 就毫无证明力（查错对象）。对照组显示不存在路径 404、随机顶层 200，说明这个 401 是**该端点的鉴权拦截**——端点真实存在、路由已注册、服务在运行。

**三环代码能力只读核查**（不改不写）：

- 连接器：`/ragflow/api/apps/restful_apis/connector_api.py` 存在
- 深度解析：`/ragflow/deepdoc/`（`parser`/`server`/`vision`）+ `document_api.py`、`chunk_api.py` 存在
- 三索引检索：`rag/nlp/search.py` 的 `Dealer.search` / `hybrid_similarity` / `retrieval` / `retrieval_by_toc` 存在
- 图谱索引：`/ragflow/rag/graphrag/`（`general`/`light`/`ner`/`entity_resolution.py`/`search.py`）完整实现存在

> **一处差点报错**：初次查 `/ragflow/graphrag/` 不存在，险些判定「v0.26.4 无图谱能力、准出②的图谱要求无解」。多查一层发现图谱模块在 **`/ragflow/rag/graphrag/`**。与 T2.09「差点误判 TR-7 失效」同源——**下结论前必须把否定命题也验证一遍**。

**处置**：挂账为 E1 前置，E1 真机须用本轮自有实例补：① 取 API Key ② 建数据集 ③ 上传样本→解析→检索各一次。
