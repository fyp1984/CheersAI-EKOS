## 一、结论（先看这里）

- **四类清单已齐**：Python 依赖（64 个第三方）、容器镜像（4 个）、模型（6 项）、云端服务（1 项），组件-版本-来源-许可证均可核。

### 5.2 另发现两项（建议上报法务）

| 对象 | 许可证 | 风险点 | 我方场景 | 技术侧可选处置 |
|---|---|---|---|---|
| Redis 7.4.1 | RSALv2 / SSPLv1（**非 OSI**） | RSALv2 禁止「将软件商业化或作为托管服务提供给他人」；SSPLv1 要求若作为服务提供须公开管理层源码 | 官方口径：内部使用（internal usage）无变化；构建「利用 Redis 但不与 Redis 竞争」的方案无影响。我方是**在甲方环境内私有化部署、由甲方自用**，非我方运营托管服务 → 按官方口径风险低 | ① 保持独立部署、仅走 Redis 协议调用（本来就是，不改代码）；② 若法务有顾虑，评估 Valkey（Apache 2.0，Redis 7.2.4 分支）或降级 Redis 7.2.x（BSD-3）——**均须走变更记录改冻结表，不得顺手改** |
| MinIO | **AGPL v3.0**（+ 商业许可） | 官方措辞：若通过网络分发 / host / 创建衍生作品，**无论是否修改过 MinIO**，须以 AGPL 公开组合作品完整源码 | 我方把 MinIO 作为系统组件随交付部署到甲方内网，通过 S3 API 调用（未链接其代码、未修改）→ 衍生作品认定存在解释空间；AGPL 的 network 条款通常针对「向公众提供服务」，甲方内部自用一般不触发 | ① 保持独立进程 + 仅走 S3 API（降低衍生作品认定风险）；② 采购 MinIO 商业许可（Standard $10/TB/月 起）；③ 评估替代（甲方既有对象存储 / 其他 S3 兼容实现）——**须法务先定性，再选路** |

> 这两项不属于 §9.5 点名范围，但都直接影响「能不能把这套东西交付给甲方」。
> **SBOM 的价值就在这：Q1（9/7）前把雷挖出来，而不是等交付前才发现。**

### 5.3 处置决策（2026-09-05 拍板 · 分阶段）

**决策**：MVP 阶段**保留 Redis 与 MinIO 现状**；进入商业交付阶段时，更换为无争议替代，或由甲方自行采购、我方做对接。**本阶段不阻塞、不改 §3.7 冻结版本表。**

**⚠️ 一处判断校准**：决策方向正确，但「因为 MVP 完全开源所以不存在商务风险」这个**理由不成立**，需要换成下面这张表。许可证义务触发与否，取决于**交付形态**（你怎么把东西给出去），而不是**你自不开源**：

| 交付形态 | Redis 7.4.1（RSALv2 / SSPLv1） | MinIO（AGPL v3.0） |
|---|---|---|
| **MVP 阶段**：自用 + 开源 | 不触发（内部使用） | 不触发 |
| **私有化交付**：部署到甲方内网、甲方自用 | **低**（我方不运营 Redis 托管服务，非 SSPL 场景） | **取决于衍生作品认定**：独立进程 + 仅走 S3 API、未链接未修改，按 mere aggregation 一般不触发；甲方内网自用也一般不满足 AGPL 第 13 条的「向公众提供」 |
| **我方托管运营**（若未来做托管版 / SaaS） | **触发** SSPL（作为服务提供须公开管理层源码） | **触发** AGPL 第 13 条 |

**真正要盯的是第二条**（私有化交付）——这也是本项目当前的形态。

**AGPL 传染的不是「能不能卖」，而是「甲方能不能闭源二开」**：若组合作品被认定为衍生作品，整体须以 AGPL 分发（Apache 2.0 代码可以并入 AGPL 作品，法律上走得通），代价是**我们想保持宽松的部分被一起升级为 AGPL**。对本次 POC 无影响；对「甲方拿去闭源二次开发」的商业条款是实质约束。

**现在就该做的（零成本、且能降低未来认定风险）**：
1. 保持 Redis / MinIO 为**独立进程**，仅通过 Redis 协议 / S3 API 调用，**不链接其代码、不修改、不打包进自有镜像**（本项目当前已是此形态，写下来是为了别在后续开发里破例）。
2. 交付介质里随附本 SBOM，让甲方知悉组件与许可证（信息透明本身也是 §9.5 的合规动作）。

**商业交付阶段的复查触发条件**（满足任一即回头处理，不得默认沿用）：
- 甲方合同中出现「闭源二次开发」「源码归属」「可转授权」条款；
- 我方开始提供托管运营 / SaaS 形态；
- 甲方安全或法务部门在评审中就此提出问询。

**届时三条路径**：① 更换为无争议替代（Redis → Valkey / 降级 7.2.x；MinIO → 甲方既有对象存储或其他 S3 兼容实现）；② 甲方自行采购 MinIO 商业许可，我方做对接；③ 采购我方侧商业许可。**均须走变更记录改冻结版本表，不得顺手改。**
