# 03 · 版本零漂移与依赖锁定（TR-4）

## 冻结版本表在哪

`60.90.03` §3.7 + `tools/gate/gate_baseline.json` 的 `TR-4.components`。
门禁逐项 diff，**差异数 = 0 才通过**。任何升级须走变更记录，**不得"顺手升"**。

## 三条铁律

### 1. 依赖一律 `==` 精确锁定，零范围声明

```toml
# ✗ 错
"mypy>=1.13",

# ✓ 对
"mypy==2.3.1",
```

**实证**：`mypy>=1.13` 曾静默漂到 2.3.1，跨大版本无人察觉。
工具链一漂，同一份代码昨天绿今天红 —— 门禁就失去可复现性。

### 2. 注释不得顶替实际声明

门禁会先剥掉行注释（`#` / `--` / `//`）再做版本匹配。

**真实事故**：`pgvector` 实锁 0.5.0，注释写着冻结的 0.8.0，门禁判「0.8.0 在位」。
**让注释满足版本校验，等于拿文档顶替现实** —— 文档永远写对的，环境未必。

### 3. 开发环境端口避开交付冻结段

`60.90.03` §3.8 冻结端口：`8080 / 8000 / 8001 / 8002 / 5432 / 6379 / 9000 / 9001`。

开发环境 compose 已改用 `15xxx / 19xxx / 18xxx` 段（主机侧）。
**compose 的主机侧端口（冒号左边）落在冻结段即违规**；容器侧是各服务标准端口，改不得也不必改。

## 两个已知的"同名不同物"陷阱

### pgvector

| 是什么 | 冻结版本 | 钉在哪 |
|---|---|---|
| PostgreSQL **服务端扩展** | 0.8.0 | 镜像标签 `0.8.0-pg16-bookworm` |
| PyPI **Python 客户端** | 最高只有 0.5.0 | `pyproject.toml` |

两者版本号体系完全独立。**拿客户端去对扩展的冻结值，会产生一条永远消不掉的 FAIL。**

### PostgreSQL 小版本

镜像标签只编码主版本（`pg16`），**16.6 钉不住**。已按用户拍板接受 16.x 滚动：
判据保留 `frozen: "16.6"` 不改（否则丢信息），另加 `match: "major"` 声明比较粒度，
并配两条方向相反的断言（16.9 认可、17.1 不认）锁死边界。

## 改依赖的标准动作

```bash
# 1. 改声明
uv add <pkg>==<精确版本>          # 运行时
# 开发依赖走 [dependency-groups]（PEP 735），裸 uv sync 即可装齐

# 2. 更新锁
uv lock

# 3. 装进环境
uv sync

# 4. 门禁
make gate
```
